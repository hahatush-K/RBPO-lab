# Маршрутизация курьерской доставки (вариант 8)

REST API на Spring Boot для планирования курьерских маршрутов: отправления назначаются на остановки маршрутов, курьер проходит маршрут и отмечает доставку. Данные хранятся в PostgreSQL.

## Предметная модель

| Сущность | Путь | Поля |
|---|---|---|
| Пользователь (`User`) | `/api/users` | name, email |
| Отправление (`Shipment`) | `/api/shipments` | senderId (→ пользователь), address, mass, status |
| Маршрут (`Route`) | `/api/routes` | date, maxMass (ограничение общей массы), status |
| Остановка (`Stop`) | `/api/stops` | routeId (→ маршрут), address, orderNumber |
| Назначение (`ShipmentAssignment`) | `/api/shipment-assignments` | shipmentId, stopId, status |

Связи: у пользователя много отправлений; у маршрута много остановок; назначение связывает отправление с остановкой (многие-ко-многим с собственным статусом).

Статусы:
- отправление: `NEW` → `ASSIGNED` → `IN_TRANSIT` → `DELIVERED`
- маршрут: `PLANNED` → `IN_PROGRESS` → `COMPLETED` (или `PLANNED` → `CANCELLED`)
- назначение: `PENDING` → `DELIVERED` (или `CANCELLED`)

## CRUD

Для каждой сущности: `GET /api/{resources}`, `GET /api/{resources}/{id}`, `POST`, `PATCH /{id}`, `DELETE /{id}`.
Ответы: 200, 201 (с `id`), 200, 204. Нет объекта — 404, нарушены ограничения — 409, неверные данные — 400.
Удаление каскадное: при удалении пользователя удаляются его отправления, маршрута — его остановки, и так далее вместе со связанными назначениями.

## Бизнес-операции

| Операция | Запрос | Условия | Результат |
|---|---|---|---|
| Назначить отправление на остановку | `POST /api/shipments/{id}/assign` `{"stopId": "..."}` | отправление `NEW`; маршрут остановки `PLANNED`; масса назначенных отправлений + масса этого не больше `maxMass` | создаётся назначение `PENDING`, отправление `ASSIGNED` |
| Снять назначение | `POST /api/shipment-assignments/{id}/unassign` | назначение `PENDING`, маршрут `PLANNED` | назначение `CANCELLED`, отправление снова `NEW` |
| Начать маршрут | `POST /api/routes/{id}/start` | маршрут `PLANNED`; дата не позже сегодняшней (по времени сервера); есть хотя бы одно назначение `PENDING` | маршрут `IN_PROGRESS`, отправления `IN_TRANSIT` |
| Отметить доставку | `POST /api/shipment-assignments/{id}/deliver` | назначение `PENDING`, маршрут `IN_PROGRESS` | назначение и отправление `DELIVERED`; если доставлено всё, маршрут сам становится `COMPLETED` |
| Отменить маршрут | `POST /api/routes/{id}/cancel` | маршрут `PLANNED` | маршрут `CANCELLED`, его назначения `CANCELLED`, отправления снова `NEW` |

Если условия не выполнены, возвращается 409 с пояснением в поле `message`. Текущее время определяет сервер.

## Целостность данных

- Ограничения БД: внешние ключи, `mass > 0`, `max_mass > 0`, `order_number > 0`, допустимые значения статусов (CHECK), уникальные `email` и пара (маршрут, порядковый номер остановки), у отправления не больше одного действующего назначения.
- Каждая бизнес-операция выполняется в одной транзакции: либо применяются все изменения, либо ни одного.
- Перед операцией блокируется строка маршрута, поэтому две операции над одним маршрутом не выполняются одновременно (например, два отправления не смогут вместе превысить лимит массы).
- Статусы можно менять через PATCH (это обычный CRUD), но бизнес-правила проверяют только бизнес-операции.

## Запуск

Нужны JDK 21 и PostgreSQL.

1. Создайте роли и базу (один раз, от суперпользователя):
   `psql -U postgres -v owner_pass=ПАРОЛЬ1 -v service_pass=ПАРОЛЬ2 -f db/setup.sql`
   `demo_owner` владеет схемой, `demo_service` может только читать и изменять данные и не может менять структуру.
2. Скопируйте `.env.example` в `.env` и укажите те же пароли (файл `.env` не попадает в git).
3. Инициализируйте схему и тестовые данные: один раз запустите приложение с профилем `db-init` (в IntelliJ: Run → Edit Configurations → Active profiles: `db-init`). Повторный запуск с этим профилем пересоздаёт схему с чистыми данными.
4. Запустите `Rbpo2026Application` без профиля. Приложение работает на `http://localhost:8080`.

## Проверка

Импортируйте `postman/courier.postman_collection.json` в Postman и запустите коллекцию (Run collection). Папка «CRUD» проверяет все пять сущностей, папка «Сценарий» проводит данные через все бизнес-операции, включая запрещённые случаи (409).
